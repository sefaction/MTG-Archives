# Commit expired-batch deletion authority before removing files

Related to #305 and release tracker #310. This completes one cleanup/database rollback boundary; neither broad tracker is complete.

`purgeTrashedAcquisitionPhotos` previously marked a session expired, unlinked up to 25 photos and marked their rows purged inside a single database transaction. A rollback after the file operations could discard the expiry/purge records while leaving the bytes removed. An uncaught transaction failure also stopped the remaining selected batches. The existing date checks independently refuse restoration after the seven-day expiry; this defect does not establish a demonstrated user restoration bypass.

Expiry now commits before any file discovery or unlink. Each photo then takes the session lock, rechecks the durable expiry, run identity, correction pins and current photo, removes its owned files and commits the purge marker. A failed photo transaction leaves durable expiry and a pending marker; retry tolerates already missing files. Counts advance only after successful transaction completion. A failed batch leaves other selected batches eligible for processing.

The seven-day rule, scanner-drain check, correction-pin protections, owner-scoped records and bounds of five batches / 25 photos per batch remain. Photo transactions retain the existing 30-second timeout. No schema, retention duration, quota, browser, recognition or Inventory policy changes are included. Existing #979 allocation/upload work, correction-directory durability and #958 language work retain their owners.
