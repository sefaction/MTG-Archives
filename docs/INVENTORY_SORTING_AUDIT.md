# Inventory sorting navigation (#703)

Sortable Inventory and Public inventory headings now load the server-ordered page through ordinary links. A normal click or keyboard activation preserves the active filters and view preferences, returns to the first page, remembers scroll position and replaces the current history entry. The active heading shows an arrow and `aria-sort`; unsupported selection/action/count headings remain plain text. Modified clicks retain normal browser link behavior. This uses a full page navigation, so sorting briefly loads the page instead of applying a component response.

## Baseline and cause boundary

The report's screenshot shows Public inventory with Equipment, League 2026 and three owner filters. Issue #704's closed drawer-filter question is separate; its intentional broader detail context is preserved.

On the unchanged application, four simple cases and a controlled 12-card three-owner Public scenario initially passed. The grouped fixture initially selected the wrong column because grouped rows omit selection; its selector was corrected. An earlier screenshot showed a loading screen despite an earlier row assertion, so later isolated-page checks wait for requests to settle before checking rows.

The strengthened five-case baseline had four passes and one failure in regular exact Inventory. Clicking Total cards from Name ascending sent a quantity-descending component request, but the URL stayed Name ascending for the original 10-second assertion. Three isolated repeats then had two passes and the same failure once. The failed trace records HTTP 200 in about 64.5ms, correct quantity-sort properties and rows, no redirect or streamed error chunk and no recorded browser error. The internal cause of the client not applying the completed response remains unknown. This is a related shared-workspace failure, not proof of all-column failure on the reporter's Public deployment.

The fix bypasses that failed response-application path only for sort headings. Backend comparisons, ownership, private/public visibility, browsing modes and other client navigation retain their existing behavior. Existing selection already clears when the ordered row query changes. These checks qualify navigation and covered ordering; they do not independently certify every metadata comparator or production deployment.
