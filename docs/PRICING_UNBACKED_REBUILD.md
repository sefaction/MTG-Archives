# Pricing full rebuild source coverage

Related to #857, parent recovery #854 and regression parent PR #856.

A full rebuild must visit keys that exist only in current summaries. Otherwise its source-only UUID/scope enumeration skips stale views and can mark readiness fresh while old prices remain visible. On a consistent local copy containing 3,036,364 raw observations, the old command completed but an independent weekly audit found 210 extra rows across 136 UUIDs absent from raw history and the archive basis. Why their source became absent is unknown; no fixture origin or WAL-failure attribution is inferred. The earlier archive retains the rows as evidence.

Source 01abe3766de9b619f7f934bbc3f78af467f38b49 enumerates UUIDs and complete provider/finish/type/currency scopes from current daily, scope, weekly, monthly and yearly views alongside the existing raw and archived-scope inputs. The existing refresh then removes a view with no authoritative basis or rebuilds it from raw/archive data. The refresh SQL, source/archive tables, historical jobs, chunk size and readiness/error protocol are unchanged. Current views select work; they do not become price authority.

The regression adds two cases: an entirely source-absent UUID and an unbacked scope on an active UUID, each present in all five current views. The unchanged command fails the test; the new selector passes, including the existing correction, failed-rebuild, idempotence and raw/job/run/log conservation checks. Required PostgreSQL import integrity also retains its archive-aware refresh/rebuild controls, so legitimate activated archive-only observations remain covered.

For the copied-history check, compare the consistent archive with all restored table contents, preserve source/archive/history fingerprints across recovery and independently compare every field of all five projections. COPY row order is not a content identity: use canonical sorted per-row hashes with duplicate cardinality, row counts and byte counts. The failed ordered comparison, failed synchronized-scan hypothesis and original scope-validator timeout remain recorded. The optimized validator keeps the same statement deadline and uses the already proven one-to-one daily/source relation rather than joining a materialized multi-million-row points set twice. Exact qualification results, current-head CI, cumulative commits and the installed maintenance-tool image are recorded in the PR and worker checkpoint.

This selector fix does not supply a concurrent-writer fence, restore absent raw observations, finish an interrupted provider import, update app-card projections or explain PostgreSQL WAL ENOMEM. Actual shared recovery remains under #854, with a current backup and exclusive-writer preconditions. The automatic pricing worker is unchanged; only the manually invoked full-rebuild command changes.
