# Printing worker memory under the existing bound

Issue #753 records a real printing-native SIGKILL at its1GiB cgroup limit during six scanner inputs and four later reference rereads. The eventual successful retries do not establish an uninterrupted reliable run. Registration resolution, feature limits, deadlines, reference-cache bounds and container memory must remain unchanged.

The reference manifest is now decoded with an object hook retaining only printing's required identity, file, digest and optional public preview URL. Names, printing catalogue fields and verified-stat metadata remain in the immutable SHA-verified file; they are not duplicated in the printing process. Card/face identity, reference counts, source-path containment, exact image hashes, stamp annotations and preview image hashes retain their existing checks. Caller metadata is not mutated. Every successful frame also collects released objects and returns unused glibc pages after the image/registration temporaries have left scope. Live reference arrays stay cached under their existing bounds. No pixels or recognition settings are reduced.

31 native printing guards pass, including retained identity/preview values, unavailable optional URL, bounded output, registration/stamp/detail controls and allocator cleanup. Two ordinary six-input scanner/browser runs pass in an isolated local Docker project with the existing worker limits. The final repeat took 131,643 ms: six primary reads, four reference rereads, ten catalogue passes and ten printing passes all completed on their first attempt. The complete and physically clipped controls skipped refinement. Original downloads retained their digests, desktop/320px review worked, Inventory remained empty and fixture cleanup reported zero failures.

The final printing cgroup peak was 1,036,271,616 bytes within its unchanged 1,073,741,824-byte limit; memory.events reported zero max/oom/oom_kill events, and idle memory after the run was about 423 MB. The previous image reached the limit and killed its native child. Exact comparison against successful observations from that failed run found unchanged source dimensions, candidate/reference identities, geometry, stamp evidence, detail measurements and preview digests across ten jobs and 120 candidate faces. Only generation identity and elapsed time were excluded. See [the aggregate qualification record](../tools/acquisition-eval/printing-memory-qualification.json).

This is a bounded development workload, including four transformations of one physical card. It leaves roughly 36 MiB peak headroom and does not qualify every accepted image size, sustained production load, independent accuracy or throughput. Larger-image memory qualification remains follow-up work. Native generation identity includes the changed worker source. Private images, full traces and snapshots stay local.
