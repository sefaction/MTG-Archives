# Printing worker memory under the existing bound

Issue #753 records a real printing-native SIGKILL at its 1 GiB cgroup limit during six scanner inputs and four later reference rereads. Eventual successful retries did not establish an uninterrupted reliable run. Registration resolution, feature limits, deadlines and container memory remain unchanged.

The reference manifest is now decoded with an object hook retaining only printing's required identity, file, digest and optional public preview URL. Names, printing catalogue fields and verified-stat metadata remain in the immutable SHA-verified file; they are not duplicated in the printing process. Card/face identity, reference counts, source-path containment, exact image hashes, stamp annotations and preview image hashes retain their existing checks. Caller metadata is not mutated. Registration and frame completion release unused allocator pages. Repeated runs with only those changes still approached the limit (1,062,137,856 bytes), so retained reference-array storage is now capped at 64 MiB instead of 128 MiB; the 48-entry bound remains. Eviction reloads the same fully verified references and can cost extra extraction time. No pixels or recognition settings are reduced.

31 native printing guards pass against the final built image, including retained identity/preview values, unavailable optional URL, bounded output, registration/stamp/detail controls, eviction/reload integrity and allocator cleanup. Cold and repeated ordinary six-input scanner/browser runs pass in an isolated local Docker project with the existing worker limits (112,703 and 125,405 ms). Each produces six primary reads, four reference rereads, ten catalogue passes and ten printing passes. The cold run completes every executed job on its first attempt; the repeated run deliberately kills an active OCR native child and recovers its same job on attempt two. All printing jobs complete on attempt one. Complete and physically clipped controls skip refinement. Original downloads retain their digests, desktop/320px review works, Inventory remains empty and fixture cleanup reports zero failures.

The final printing cgroup peak across both runs is 1,000,329,216 bytes within its unchanged 1,073,741,824-byte limit; memory.events reports zero max/oom/oom_kill events, leaving about 70 MiB observed peak headroom. Idle memory after the repeated run is about 378 MB. Exact comparison against successful observations from the original failed run finds unchanged source dimensions, candidate/reference identities, geometry, stamp evidence, detail measurements and preview digests across ten jobs and 120 candidate faces in each final run. Only generation identity and elapsed time are excluded. See [the aggregate qualification record](../tools/acquisition-eval/printing-memory-qualification.json).

This is a bounded development workload, including four transformations of one physical card. It does not qualify every accepted image size, sustained production load, independent accuracy or throughput. Larger-image memory qualification remains follow-up work. Native generation identity includes the changed worker and cache-policy source. Private images, full traces and snapshots stay local. Earlier unexpected primary worker restarts are tracked separately in #755; no host-wide uninterrupted-operation claim is made.
