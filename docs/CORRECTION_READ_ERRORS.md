# Preserve correction-original read failures

Related to existing #305 and release tracker #310. This is one bounded storage-error repair; both trackers retain their other acceptance criteria.

`readCorrectionBlob` previously closed its handle in `finally`. If reading or checking the original failed and closing also failed, only the close error escaped. In particular, a primary `EACCES` could become `EIO`, losing the worker's actionable retry classification, or become `ENOENT`, incorrectly entering the missing-original fallback.

The reader now attempts close after either read outcome and retains every failure in order. A single failure retains its exact identity. Combined failures expose the primary as `cause`, retain both entries in `AggregateError.errors`, and copy only the primary string `code`. Digest/length errors never inherit a secondary `ENOENT`. Successful reads still return the same bytes only after a successful close. Existing owner directories, path/no-follow checks, digest/length bounds and callers remain unchanged.
