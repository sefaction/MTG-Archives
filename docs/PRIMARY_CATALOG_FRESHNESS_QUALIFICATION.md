## Result and bounded policy

The primary OCR process previously refreshed its startup catalog only when optional reference refinement was enabled. The existing refresh check now applies in both modes. After more than 30 seconds since the last completed snapshot load, the next between-jobs iteration refreshes before admitting recognition work. An already running job, native preparation and the snapshot read can extend wall-clock freshness; this is not a hard 30-second HTTP or per-photo deadline. Paging, RepeatableRead, exact-content digest, unchanged index/map reuse, failed-refresh fatal behavior and existing timeout/lease/resource policies are unchanged. Optional reference refinement remains independently controlled.

Only the existing condition in scripts/acquisition-recognition-worker.ts changes application behavior. The original surrounding script matches the base exactly apart from that condition/comment.
