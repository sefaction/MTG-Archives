# Canonical correction evidence persistence

Addresses [#746](https://github.com/sefaction/MTG-Archives/issues/746). A printing evidence bundle recorded a canonical hash and23,147-byte count but persisted four slightly different finite geometry coordinates; canonical readback was23,143bytes. Its complete source job reconstructs the expected original hash and size. The historical evidence and failed integrity checks remain preserved.

A controlled PostgreSQL transaction isolates the write boundary using the four reported finite coordinates, ordered arrays and quoted Unicode text. Prisma's JSON-object create changes the values; both normal JSON readback and a direct payload::text check fail the original hash/size. Binding the canonical JSON as text and casting it to JSONB preserves both readbacks. The transaction is deliberately rolled back, and exact fixture account/evidence absence is checked afterward. Earlier probe setup rejected a short synthetic display key under the existing bounds constraint; it also rolled back. Initial helper quoting and host-port guard errors occurred before regression writes; their diagnostics remain local.

New evidence uses one parameterized INSERT of the canonical text already used for hashing and byte accounting. UUID identity, database timestamp defaults, the owner lock, owner/hash deduplication,512KiB bound and atomic account update remain. All evidence roles use the same helper. No schema/migration, retention, sampling, ownership or Inventory policy changes are included. Historical payloads are not rewritten or rehashed.

The real database regression is part of required Acquisition PostgreSQL integrity verification. It checks exact finite geometry through normal and raw-text reads, hash/UTF-8 byte equality, Unicode/quotes/backslashes, array order/null/tiny/negative values, owner isolation, concurrent replay without duplicate charging, transaction rollback and oversized rejection without charging. Every exact generated fixture account and evidence row is removed afterward.
