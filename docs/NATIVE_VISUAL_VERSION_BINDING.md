This opt-in qualification runs the canonical visual component, content-locked
VGG16 weights, real embeddings/SIFT, production native generation/transport,
upload/canonical preparation, queue, visual handler and completion/review fences.
The source images/catalogue are synthetic. It does not measure optical accuracy,
qualify an installation's complete catalogue, 150,000-copy scale, physical
scanning, sustained resource behavior, deployment or broad #304/#307/#310 scope.

## Complete fixture, explicit partial refusal

cards (one with both image-bearing faces) and one digital card. The real
reference producer plans all six paper faces. Only public-image transport is
substituted with deterministic synthetic JPEGs; normal URL/image validation,
atomic writes, hashes, SQLite states, snapshot/export and completeness logic run.

One READY/five PENDING faces produce a genuinely partial index. The normal
loader and production native-generation path must refuse it. Only after every
planned face is READY does the ordinary index producer publish a complete
six-reference generation, with actual encoder vectors. No completeness flag is
edited and no partial-index override is used. A metadata-only second catalogue
passes the normal exact-feature reuse checks and publishes a distinct complete
generation. Both immutable manifests and their exact generation files remain
available when the current pointer changes.

The VGG16 file must match the existing `image_encoder.py` SHA-256 lock
`397923af8e79cdbb6a7127f12361acd7a2f83e06b05044ddf496e83de57a5bf0`.
A detached same-size, one-byte-changed copy must fail the actual encoder's hash
check before model construction; the real mounted weights stay unchanged.

## Actual queue/native checks

`verify-native-visual-version-binding.ts` requires root in the canonical Linux
component, `MTG_NATIVE_VISUAL_VERSION_FIXTURE=1`, the exact disposable host
`nativevisual304-pg`/database `acquisition_native_visual304`, and no pre-existing
users, cards, Inventory or acquisition sessions. It uses only owned synthetic
rows/files. Never point it at an installation or retained review database.

- The real descriptor binds the published index, source catalogue, locked
  encoder/package/runtime sources and CPU execution. Normal startup/generation
  checks preserve the 30-second descriptor and 120/180-second processing/lease
  deadlines; the native parser still drops privileges and excludes credentials.
- Three actual uploads/canonical jobs retain distinct physical photo identities.
  Equal-byte photos share one completed visual observation without another
  native request. A different original performs actual inference. Actual
  nearest-image and geometric candidates retain their source identities and
  require review; no label or expected vector is injected into inference.
- A saved human review supersedes a late real result without changing that
  decision or Inventory. Switching the pointer keeps the old native process
  pinned to its immutable generation until the normal generation refresh.
- Admission against an incompatible descriptor refuses before native work. A
  genuine result from the old child is refused against the new generation;
  explicit outer flags prevent a swallowed assertion from passing this control.
  The production refresh shuts down the old child before opening the new one,
  whose actual output carries the new index/metadata identity and misses reuse.
- Original bytes and initial job inputs remain exact. A seeded quantity-two
  Inventory row and all audits remain unchanged; no acquisition commit occurs.
  Native shutdown precedes exact-owned row/file cleanup. Full-row fingerprints
  of every original public table must be restored, including migrations.
  Primary, native-shutdown, row/file cleanup and disconnect failures are retained
  independently; uncertain termination/restoration preserves fixture evidence.
