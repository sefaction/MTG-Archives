# Correction original capture uses database time

Issue [#781](https://github.com/sefaction/MTG-Archives/issues/781) concerns the independent correction-library original-copy queue. Its admission and lease issue previously used worker time, although publication checked the database clock. A worker one hour ahead issued a two-minute lease about one hour too far in the future. A slow worker could issue an already expired lease; differing worker clocks could admit retries early or revoke live copy authority.

The unchanged production helper failed a real disposable PostgreSQL regression with +1 hour application time. The repair uses PostgreSQL time for admission, post-owner-lock revalidation and lease issue, publication timestamps, both capacity waits, and the atomic failure/retry compare-and-set. Existing token fencing, owner turns, reservations, pins, two-minute leases and one-minute delays remain. The 64 decimal GB allowance and 2% controls are unchanged. There is no historical worker-incident attribution.

`scripts/verify-correction-capture-clock.ts` runs inside the required acquisition PostgreSQL suite. It changes only no-argument application Date construction/Date.now, preserving explicit fixture dates and restoring Date in finally. Real database controls exercise ±1 hour skew, database-relative lease bounds, another fast worker, future retries, a slow successful publication, expired and superseded tokens, failed-copy backoff, both capacity waits, reservation conservation and no Inventory writes. No private photos or models are needed.
