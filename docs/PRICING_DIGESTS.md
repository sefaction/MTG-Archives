# Opt-in Pricing movement digest

Issue #335 follows the owned movers view (#329). Each inventory owner can enable a daily in-app digest under Settings → Pricing movement digest. The default is off, with a $2 per-card change threshold. Provider, finish, price type, currency, absolute/percent/either rule, minimum percent, and minimum prior price are configurable. A digest is scoped to currently owned exact printings and one source/currency/finish; quantity-weighted collection impact ranks the results. At most 100 detailed rows are retained in one notification, with the full eligible count displayed.

The existing notification worker checks the prior UTC observation day after 02:00 UTC. It requires a ready summary synchronized with the latest raw import, and only considers a price ingested after the user enabled the current settings. A quiet owner is rechecked after 30 minutes so a delayed import can still appear. A nonempty digest has one notification per owner/observation date; worker restarts and replay do not enqueue a second one. The notification is an in-app item only. Email and webhook delivery are deliberately not enqueued by this first release.

Each row captures the previous/current observed dates and prices, exact printing, owned quantity at generation, source and collection impact. It links to live card history while the card remains owned. The snapshot explicitly records its generation time: later source corrections or inventory changes appear in live history, but do not silently rewrite or duplicate a digest already sent. A correction arriving after the next-day window has passed cannot create an alert for the old observation date; this limitation should be reviewed before considering delivery beyond in-app notifications.

The Settings page shows enabled/paused state, last sent/failed state, and recent digests. No preference or notification reveals another owner's holdings. Local Docker is the test target; production deployment and PR merging require separate approval.
