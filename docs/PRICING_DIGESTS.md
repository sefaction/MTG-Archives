# Opt-in Pricing movement digest

Issue #335 follows the owned movers view (#329). Each inventory owner can enable a daily in-app digest under Settings → Pricing movement digest. The default is off, with a $2 per-card change threshold. Provider, finish, price type, currency, absolute/percent/either rule, minimum percent, and minimum prior price are configurable. A digest is scoped to currently owned exact printings and one source/currency/finish; quantity-weighted collection impact ranks the results. At most 100 detailed rows are retained in one notification, with the full eligible count displayed.

The existing notification worker checks the prior UTC **import day** after 02:00 UTC. It requires a ready summary synchronized with the latest raw import, and only considers a price ingested after the user enabled the current settings. A quiet owner is rechecked after 30 minutes so a delayed import can still appear. After an outage, it resumes from a per-owner cursor and produces one in-app digest for each missed import day with relevant movements, oldest first, up to three days per worker run. It scans at most the last 90 import days and continues on later runs if more days remain. A nonempty digest has one notification per owner/import day; worker restarts and replay do not enqueue a second one. Recovered digests mark that their owned quantities reflect generation time. Email and webhook delivery are not enqueued.

Each row captures the previous/current observed dates and prices, exact printing, owned quantity at generation, source and collection impact. It links to live card history while the card remains owned. A correction imported later for an older observed date (within 90 days) appears in the next import day's digest and is labeled as a correction, even when a newer observation already exists. A same-price replay for that date is suppressed. The snapshot explicitly records its generation time: later source corrections or inventory changes do not silently rewrite a digest already sent. Corrections outside the 90-day daily window require an archive/rehydration path under #330; they are not silently included in an inaccurate trend.

If a later source correction drops a movement that was actually shown in an earlier digest below the owner's current threshold, the next import-day digest includes a separate corrected-alert entry. It shows the originally alerted and corrected prices and links to live history while the card remains owned. Unshown rows beyond the 100-detail cap, no-longer-owned printings, and price changes that still meet the threshold do not produce retractions. Previously reported corrections are deduplicated from stored digest snapshots; the original snapshot stays unchanged. This is still an in-app notification with no email or webhook job.

The importer updates a changed value at the same printing/source/finish/type/currency/observed date and increments its revision count; it leaves an identical replay untouched. The daily projection carries that revision marker. A source-revision counter keeps Pricing reads and digest checks stale until all affected summaries refresh, even though the corrected raw row retains its original ID. Import job history reports inserted, corrected, and skipped counts separately.

The Settings page shows enabled/paused state, last sent/failed state, recent digests, and the selected source's last update. It marks the source stale after 72 hours with no new data. Source staleness does not create a separate notification. No preference or notification reveals another owner's holdings. Local Docker is the test target; production deployment and PR merging require separate approval.
