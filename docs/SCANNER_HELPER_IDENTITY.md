# Prospective scanner helper identity (#304)

The scanner run previously preserved its authenticated agent, execution, device and settings, but not the helper payload that claimed it. The latest discovery pulse cannot reconstruct that history. Helper 0.4.4 now reports the SHA-256 and loaded module ID of its actual `Mtg.ScannerAgent.dll`, together with helper, protocol and declared NAPS2 SDK versions. This is authenticated self-reported provenance, not signing, remote attestation or identification of every installed dependency/native driver.

The site advertises support in its authenticated poll. Before preparing a new source, the helper reads its managed payload through one handle, verifies its metadata module ID against the loaded module, hashes the bytes and freezes the report in its execution journal. An unsupported or replaced payload refuses to start. The initial claim atomically persists the report with the execution. The helper checks the site's exact echo before authorizing feed. Retried claims must match every identity field; a later pulse or transfer cannot rewrite it. New photo source metadata inherits the frozen run identity, preserving the original source-to-canonical-job lineage.

The migration adds one nullable JSONB column without backfilling. Older helpers remain supported; older sites receive the previous claim shape. Legacy local journals and historical runs keep an unknown identity. An uncertain durable start marker also stays unknown: a retry cannot attribute that earlier attempt to its current binary. Protocol version and current agent pulse are never substituted for missing historical payload evidence. Native processing/model identity and independent recognition acceptance remain separate work.

## Author validation

- Focused protocol coverage rejects malformed, oversized or additional fields and transfer-supplied identity. Legacy claim shape remains unchanged. The actual Windows producer case runs only when supplied a report from the compiled helper; a local platform skip is explicit.
- The real PostgreSQL scanner fixture invokes the actual claim route/parser/authentication/store, checks exact claim echoes and HTTP 409 on conflicting replay, races two reports for one execution, reconnects through a fresh client and preserves known and unknown provenance. It retains identical-byte physical-copy separation, raw-byte/graph equality, recovery/stop fences, original cleanup and zero owned Inventory writes. The disposable fixture returned all 85 public-table fingerprints to their baseline.
- Windows source and self-contained checks execute `identity-selftest` without a scanner. An independent file hash is compared with the actual helper's `version` output, which then passes through the production site schema. Installer CI repeats the check against the installed payload and retains the existing source/notices/rebuild/uninstall gates. This machine has runtimes but no .NET SDK, so local C# compilation is not claimed.
- Exact revision, build/runtime receipts and current hosted results are recorded on the pull request. No physical scanner, production installation, user acceptance or historical binary reconstruction is implied. #304 and parent #302 remain open.

For a supported installed helper, `Mtg.ScannerAgent.exe version` includes the path-free report; `identity-selftest` checks its actual managed payload and compatibility contracts without connecting or discovering devices. The report alone does not prove an installation is trusted.
